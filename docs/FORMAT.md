# Формат папки задачи

На входе агента задача оформлена так же по назначению файлов, как два исходных кейса классификации и регрессии:

```text
/workspace/
  task.md
  train.csv
  test.csv
  data_dictionary.csv
  sample_submission.csv
  task.json
  agent/
    solution.py
```

Первые пять файлов соответствуют исходной структуре. `task.json` добавляет машиночитаемые метаданные. Агент вызывается как `python /workspace/agent/solution.py /workspace/task.md`; рабочий каталог — `/workspace`. `submission.csv` он сохраняет рядом с `task.md`.

| Файл | Условие |
| --- | --- |
| `train.csv` | Признаки, уникальный технический `id`, размеченный `target` |
| `test.csv` | Те же признаки и `id`, без target |
| `sample_submission.csv` | Ровно `id,target`, в порядке теста; значения — заглушки |
| `data_dictionary.csv` | Типы, роли, исходные имена, известные описания и единицы |
| `task.md` | Постановка, ограничения, метрика, правила разбиения и формат ответа |
| `task.json` | Допустимые классы, NA-токен, ключи группировки, исходный target и параметры |

В исходных двух кейсах целевой столбец называется `attack_cat` или `site_eui`. В большом и light-бенчмарках используется одно имя `target`, чтобы одно решение работало на всех задачах. Это адаптированный интерфейс, а не побайтовая копия исходных CSV. Все переименования отражены в словаре и JSON.

В Git исходная таблица хранится один раз как Parquet с закреплёнными разбиениями. `run` и `calibrate` автоматически создают CSV одного случая перед запуском. После оценки входные CSV могут удаляться с хоста и точно восстанавливаться перед повтором. Для каждого случая создаётся отдельный рабочий каталог; объединённая папка со всеми датасетами агенту не монтируется.

Evaluator сохраняет правильные ответы test отдельно в `data/v1/private`. Этот путь не доступен контейнеру агента. Наличие исходных размеченных таблиц в публичном репозитории не означает разрешение читать их во время решения: допустимы только выданные train/test текущего случая.
