# AgentML Bench Light

Компактная версия [AgentML Bench](https://github.com/Rusti3/AgentML_bench) для проверки **AI-агентов и обычных ML-решений**. В наборе **16 уникальных задач из 16 семейств**, разделённых на **4 независимые группы**. В каждой группе — **2 регрессии, 1 бинарная и 1 многоклассовая классификация**.

Можно запустить одну группу, любые две или три, либо все четыре. Интерфейс агента, метрики, эталон CatBoost, профили ресурсов и изоляция сохранены из большого benchmark. Исходные таблицы, метаданные и опубликованные разбиения включены в этот репозиторий: отдельно скачивать весь большой набор не нужно.

## Состав групп

| Группа | Регрессия: 2 задачи | Классификация: 2 задачи | Что проверяет |
| --- | --- | --- | --- |
| **1** | Airfoil Self Noise; Concrete Compressive Strength | German Credit; Dermatology | Небольшие таблицы, числовые и категориальные признаки |
| **2** | Student Portuguese Performance; Fiat 500 | QSAR Biodegradation; Student Dropout | Смешанные признаки и разные прикладные области |
| **3** | Video Game FPS Prediction; Abalone | Polish Companies Bankruptcy; Cardiotocography | В том числе обобщение на новые группы объектов |
| **4** | 5G Energy Consumption; Grid Stability (simulation) | Credit Card Default; Mice Protein | Более крупные таблицы и групповые разбиения |

Группы не пересекаются ни по задачам, ни по родственным семействам. Это четыре разных набора, а не четыре разбиения одной таблицы. Полный состав, target, размер, тип разбиения и лицензия каждой задачи закреплены в [groups.json](data/v1/catalog/groups.json). Посмотреть список ID:

```bash
python benchmark.py groups
```

В третьей группе FPS и Cardiotocography имеют групповые разбиения; Abalone и Polish Companies Bankruptcy — IID. В четвёртой 5G и Mice Protein имеют групповые разбиения, остальные — IID. Target FPS уже логарифмирован куратором и сохраняется в этой шкале. Grid Stability содержит результаты симуляции, а не реальные аварии электросети. Student Dropout использует данные первых двух семестров и не является прогнозом при поступлении.

После содержательной проверки **7 первоначальных кандидатов заменены**. Причины и ограничения всех итоговых задач описаны в [отчёте о пригодности](docs/SUITABILITY.md). В light-v1 представлены IID и групповые задачи. Временные кандидаты в этот компактный набор не включены; временные протоколы остаются в большом benchmark.

## Установка

Нужны **Python 3.12**, Git и работающий **Linux Docker на x86-64**. Docker должен иметь минимум 8 CPU и достаточно памяти для контейнера 8 GiB и служебных процессов. Таблицы с индексами выбранных задач занимают около **23 MiB**; Python-библиотеки и временные CSV занимают существенно больше. Рекомендуется 15 GiB свободного места для установки и обычных запусков Standard; длинные агентные эксперименты могут потребовать больше.

```bash
git clone https://github.com/Rusti3/AgentML_bench_light.git
cd AgentML_bench_light
python -m venv .venv
```

Активируйте окружение:

```powershell
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
```

```bash
# Linux
source .venv/bin/activate
```

Из корня репозитория:

```bash
python -m pip install -r requirements-host.txt
python setup_runtime.py
python benchmark.py audit
```

Таблицы уже включены в Git. `fetch` нужен для восстановления отсутствующих файлов из закреплённых источников; обычный первый запуск не требует повторного скачивания. Окружение агента создаётся в `runtime/linux`, данные — в `data/v1`, кэши и временные файлы — внутри клона.

## Запустить одну, две или все группы

Сначала создайте эталон для выбранного состава и профиля. Это обучение фиксированного CatBoost без LLM; оно нужно для нормированного балла. Затем запускайте своего агента или обычное решение:

```bash
# Только группа 1: четыре задачи
python benchmark.py calibrate --groups 1 --profile local8
python benchmark.py run --agent examples/solution.py --groups 1 --profile local8 --no-llm --run-id group1_check
python benchmark.py score --run-id group1_check

# Группы 1 и 3: восемь задач
python benchmark.py calibrate --groups 1,3 --profile local8
python benchmark.py run --agent /path/to/my_agent --groups 1,3 --profile local8 --no-llm --run-id groups13_v1
python benchmark.py score --run-id groups13_v1

# Все четыре группы: шестнадцать задач
python benchmark.py calibrate --groups all --profile local8
python benchmark.py run --agent /path/to/my_agent --groups all --profile local8 --no-llm --run-id all_groups_v1
python benchmark.py score --run-id all_groups_v1
```

В Windows используйте путь вида `A:\agents\my_agent`. Допускается запись `--groups 1 3`; отсутствие `--groups` означает все четыре группы. Результаты разных составов сравнивайте по одинаковым группам, а не только по общему баллу.

`examples/solution.py` предсказывает среднее или самый частый класс. Он проверяет интерфейс, а не демонстрирует сильную модель. Замените `--agent` на собственный `.py` или каталог с `solution.py` и вспомогательными файлами. Обычные ML-решения запускаются так же, как агенты; для них оставьте `--no-llm`.

Калибровки и завершённые случаи переиспользуются при совпадении сигнатур. Повтор команды с тем же `run-id` продолжает прерванный прогон. Изменение агента, состава, окружения, модели или лимита требует нового ID. Один контейнер с задачей работает одновременно, агенту по умолчанию даётся **3 часа на задачу**, эталону — **10 минут на разбиение**.

## Интерфейс решения

Агент вызывается как `python solution.py /workspace/task.md`, рабочий каталог — `/workspace`. Он получает только одну задачу:

| Файл | Что содержит |
| --- | --- |
| `task.md`, `task.json` | Условие, тип задачи, метрику и описание разбиения |
| `train.csv` | Признаки, `id` и целевой столбец `target` |
| `test.csv` | Признаки и `id`, без правильных ответов |
| `data_dictionary.csv` | Исходные имена, типы и известные описания полей |
| `sample_submission.csv` | Шаблон ответа, его значения не являются правильными ответами |

Сохраните `/workspace/submission.csv`: ровно столбцы **`id,target`**, без индекса pandas. ID, их порядок и количество должны совпадать с тестом. Классификация требует одной допустимой метки класса, регрессия — конечного числового значения. Вероятности вместо меток не принимаются.

```python
pd.DataFrame({"id": test["id"], "target": predictions}).to_csv(
    "submission.csv", index=False
)
```

Читайте инструкцию по пропускам из `task.md`: используется специальный NA-токен; строки `NA` и пустая строка могут быть категориями. [Пример решения](examples/solution.py) показывает чтение таблиц. Имена исходных таргетов, типы и известные единицы сохраняются в метаданных; интерфейс использует единое имя `target`.

Правильные ответы, исходные размеченные таблицы, другие задачи, архив калибровок и Docker socket не монтируются в контейнер. Агенту передаётся только подготовленный train/test текущего случая. Не помещайте benchmark целиком или ключи API в bundle агента.

Сопоставление с форматом двух исходных кейсов и пример дерева папки: [docs/FORMAT.md](docs/FORMAT.md).

## Метрики и баллы

| Тип задачи | Основная метрика | Дополнительные |
| --- | --- | --- |
| Бинарная и многоклассовая классификация | **Macro F1**, больше — лучше | Accuracy, Weighted F1, показатели по классам |
| Регрессия | **RMSE** в шкале таргета источника, меньше — лучше | MAE, R² |

Для Macro F1 используется определение sklearn по объединению меток в правильных ответах и предсказаниях, `zero_division=0`. RMSE разных датасетов напрямую не усредняется. Балл относительно фиксированного эталона считается по тем же формулам, что в большом benchmark:

```text
S_reg = 100 × max(0, 1 − RMSE / B_RMSE)
S_cls = 100 × max(0, (MacroF1 − B_F1) / (1 − B_F1))
```

Эталон — **CatBoost 1.2.8**: 300 итераций, depth 6, learning rate 0,05, seed 42, 8 потоков; `SqrtBalanced` для классификации. Без LLM и подбора параметров. [Параметры и препроцессинг](agentbench/reference_worker.py) одинаковы для всех задач.

Совпадение с эталоном даёт 0 баллов, улучшение повышает score; идеальное предсказание даёт 100. При `B_F1 = 1`, `B_RMSE <= 0` или сбое эталона нормировка недоступна. Сырые метрики сохраняются; другой baseline не подставляется.

Агрегация сохраняет протокол большого набора: среднее по разбиениям, вариантам и семействам, далее отдельно классификация и регрессия, затем среднее двух категорий с весами 50/50. **Дополнительно** вычисляется такая же сводка внутри каждой выбранной группы. При полном Standard-прогоне целых групп общий score равен среднему их групповых score: у каждой группы одинаковый баланс и независимые семейства.

## Где смотреть результат

`python benchmark.py score --run-id NAME` выводит и сохраняет `data/v1/runs/NAME/summary.json`:

- **`overall_score`**, **`category_scores`** — общий балл выбранного состава и две категории.
- **`group_scores["1"]`**, `group_scores["2"]` и т. д. — баллы, категории и coverage отдельных выбранных групп.
- **`complete`, `coverage`, `scored_cases`, `cases`** — полнота оценки. Неполный прогон не равен полному результату.
- **`complete_group_selection`** внутри группы — выбраны ли все её задачи. Это особенно важно при отладке через `--tasks`.
- **`results`**, **`family_scores`** — статусы задач и качество по независимым семействам.

Сырые метрики и ошибки каждой задачи находятся в `cases/<case-id>/result.json`, предсказания — в `submission.csv`, логи — в `stdout.log` и `stderr.log`. Сводка проверяет целостность сохранённых предсказаний и неизменность групп. Уже записанный валидный ответ оценивается и после таймаута. Невалидный или отсутствующий submission получает 0 при доступной калибровке; инфраструктурные ошибки и отсутствие калибровки отмечаются отдельно.

## Режимы и ресурсы

**Standard** — режим по умолчанию: одно исходное разбиение с минимальными repeat/fold IDs на задачу. **Full** использует все опубликованные разбиения выбранных групп; сначала выполните `calibrate --groups 1,3 --subset full`, затем `run` с теми же флагами.

**Smoke** сохраняет выбор до 12 небольших задач из большого протокола и предназначен для технической проверки. Он не означает все 16 задач. Для точного выбора групп используйте Standard или Full; сочетание явного `--groups` с Smoke отклоняется. `--tasks id1,id2` позволяет проверить отдельные случаи и не сочетается с `--groups`.

| Профиль | Лимиты |
| --- | --- |
| `local8` | 8 CPU / 8 GiB, без swap |
| `contest32` | 8 CPU / 32 GiB, без swap; профиль не сертифицирован на исходной машине |

Сравнивайте решения с одинаковыми группами, режимом, профилем, таймаутом, моделью и версиями окружения. Для отладки можно уменьшить `run --timeout SECONDS`; такие результаты сравнимы с тем же лимитом. Python-пакеты доступны офлайн из [окружения](requirements-linux.txt); произвольная установка пакетов в контейнере не предусмотрена.

## LLM-провайдер

Сеть агента отключена. Опциональный шлюз пропускает только model API настроенного провайдера; настоящий ключ остаётся вне контейнера. На хосте задайте:

```powershell
$env:BENCH_UPSTREAM_BASE_URL = 'http://localhost:8080/v1'
$env:OPENAI_API_KEY = '<ваш ключ>'
python benchmark.py run --agent A:\agents\my_agent --groups 1 --model gpt-5.6-luna --run-id luna_group1_v1
```

В Linux используйте `export` для переменных окружения. Дополнительные заголовки задаются JSON-переменной `BENCH_UPSTREAM_HEADERS`. Агент получает локальный `OPENAI_BASE_URL`, фиктивный `OPENAI_API_KEY` и `OPENAI_MODEL`. Reasoning effort, например `medium`, задаёт код самого агента в API-запросе. Подготовка данных и калибровка LLM не используют; запуск LLM-агента может расходовать средства провайдера.

## Данные, проверки и версии

Выбраны проверенные случаи из закреплённых TabArena/OpenML и BeyondArena. Данные хранятся однократно в каноническом Parquet; отдельные CSV создаются перед запуском. Исходные IID и групповые разбиения выбранных задач сохранены. Контрольные суммы находятся в `data/v1/catalog/assets.lock.json`, происхождение light-набора — в `groups.json`. Это адаптированная оценка, а не официальный leaderboard источников. Публичные данные могли встречаться в обучении LLM; аудит не доказывает отсутствие всех возможных утечек.

Лицензии таблиц и атрибуция: [DATA_LICENSES.md](DATA_LICENSES.md). Код проекта — MIT; данные и сторонние документы сохраняют собственные условия. Архив исходных калибровок — [published/v1](published/v1/README.md). Его результаты автоматически не подставляются в окружение нового пользователя: требуется своя калибровка.

```bash
# Проверить данные, группы и весь путь CSV-оценки без Docker и LLM
python benchmark.py audit
python -m pytest tests/test_protocol.py tests/test_sources.py tests/test_publication.py tests/test_groups.py tests/test_light_integration.py -q

# После настройки runtime — изоляция, шлюз, таймауты и реальный эталон
python -m pytest tests/test_docker.py -q

# Обновить локальные CSV/JSON/Markdown отчёты
python benchmark.py report
```

Проверки охватывают все 16 включённых задач, баланс и непересечение групп, выбор одной/нескольких групп, формулы и полноту результатов. `fetch --groups 1 --retry` восстанавливает файлы выбранной группы по закреплённым источникам. Изменение состава, разбиений или эталона требует новой версии light-набора.

Исходная light-сборка прошла 78 тестов без пропусков, включая Docker и сквозные прогоны одной, двух и всех четырёх групп. [Машиночитаемый отчёт проверки](published/v1/validation.json).
